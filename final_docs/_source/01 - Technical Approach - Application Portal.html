Technical Approach

Project: Application Portal (South Africa)
Date: 12 May 2026
Peak Applicants (estimate): 500+
Staff Users (estimate): ~5 concurrent

1) Alignment to Latest Feedback

  • POPIA Officer: Governance, enforcement, and training handled by the client’s POPIA/compliance officer. Our scope covers the full technical POPIA controls.
  • Target usage window: Applicants typically start using the portal mid-September. Admin training and final handover must occur before the opening window.
  • Load expectation: The brief indicates 500+ applicants, with a staff review team of about 5 users.

2) Proposed Architecture & Tech Stack

Application Stack (recommended)

  • Frontend: Next.js (TypeScript)
  • Backend API: .NET 8 (ASP.NET Core Web API)
  • Database: PostgreSQL
  • File storage: S3 / Blob storage with encryption
  • Identity: Cognito / Azure AD B2C / ASP.NET Identity
  • Email: SES / SendGrid equivalent
  • Monitoring: Centralized logs + alerts

Why this stack fits

  • Well-suited for workflow enforcement and strict authorization.
  • Strong auditability for stage-by-stage scoring and decision trails.
  • Secure document handling via managed encryption primitives.
  • Predictable scaling for seasonal load and burst traffic.

3) Backend Architecture (Revised Questions)

Role-based access control (RBAC)

  • Policy-based authorization per role and capability (server-enforced on every endpoint).
  • Role separation ensures each reviewer sees only relevant data (e.g. essay reviewers cannot see academic scoring or other reviewers’ scores).

Workflow state machine

  • Strict stage ordering is enforced (no shortlisting before essay + academics + document verification are complete).
  • Interview scoring allowed only once an applicant is shortlisted.
  • Final decisions allowed only after required prior stages are complete.

Race condition prevention

  • Optimistic concurrency controls on core records.
  • Stage assignment/locking rules to avoid two staff members scoring the same applicant at the same time.
  • Unique constraints to prevent duplicate scoring records.
  • Idempotency patterns for sensitive actions (submission/export) to prevent duplicates.

4) POPIA Technical Controls (From Day One)

  • Encryption in transit: HTTPS everywhere, HSTS, secure cookie/session handling.
  • Encryption at rest: Encrypted database storage, encrypted document storage, and managed keys.
  • Consent: Explicit consent capture stored with timestamp and policy version.
  • Audit logging: Who did what, when, from where, and what changed (append-only, restricted access).
  • Data export: Applicant export as a generated package with time-limited access; fully audited.
  • Deletion & retention: Policy-driven deletion/anonymisation after the cycle (with legally necessary audit retention).
  • Breach readiness: Logging + alerting, plus an incident runbook for the compliance officer’s procedures.

5) Master Scorecard (Critical Component)

A comparative scoring dashboard ranks applicants by total score, supports filtering, and exports to Excel. It pulls stage scores (essay, academics, interview) and auto-calculates rule-based points (e.g. experience, TEFL, degree), while enforcing role-based visibility so only authorized roles see consolidated totals at the correct stage.
